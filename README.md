# ЕГРЗ — ежедневная выгрузка, умные фильтры и инфографика

Ресурс, который каждый день забирает список объектов из
[Единого государственного реестра заключений экспертизы проектной документации](https://egrz.ru/)
(ЕГРЗ), приводит данные к единому виду и показывает их в дашборде с фасетными
фильтрами и инфографикой.

```
источник ЕГРЗ ──▶ нормализация ──▶ SQLite ──▶ витрина (JSON/CSV) ──▶ дашборд
   client.py       normalize.py    store.py     export.py            web/
```

---

## Быстрый старт

```bash
pip install -e .

# 1. Выгрузка. Без доступа к egrz.ru используйте --source demo:
#    синтетические данные той же формы, чтобы посмотреть весь конвейер.
python -m egrz.cli daily --source demo --demo-count 4000 --full

# 2. Дашборд
python -m egrz.cli serve          # http://localhost:8000
```

С живым источником:

```bash
python -m egrz.cli daily --source api      # инкрементально, по умолчанию
```

## Важно: контракт публичного API ЕГРЗ

**У ЕГРЗ нет опубликованной спецификации API, и его контракт меняется вместе с
сайтом.** Проверить конкретные адреса методов при разработке не удалось —
из окружения сборки исходящий доступ к `egrz.ru` и `open-api.egrz.ru` закрыт
сетевой политикой. Поэтому запрос, пагинация и сопоставление полей вынесены в
конфиг [`egrz/sources/egrz.yaml`](egrz/sources/egrz.yaml), а не зашиты в код,
и в комплекте есть команда разведки:

```bash
python -m egrz.cli discover --out data/discovery.json
```

Она перебирает кандидатов, показывает, кто чем ответил, и по **реальному**
ответу предлагает готовый блок `field_map`. Дальше:

1. перенесите `method`/`path` победившего кандидата в секцию `request`;
2. перенесите `suggested_field_map` из отчёта в `field_map`;
3. `python -m egrz.cli sync --source api --limit 50` — проверка на маленькой выборке.

Если ни один кандидат не подошёл, откройте реестр в браузере, скопируйте запрос
из DevTools → Network и добавьте его в `discovery_candidates`. Код при этом
править не нужно: весь остальной конвейер — нормализация, хранилище, витрина,
дашборд — от формы источника не зависит и уже покрыт тестами.

## Что делает нормализация

Источник отдаёт данные неровно, поэтому «сырые» поля приводятся к канону
([`egrz/normalize.py`](egrz/normalize.py), [`egrz/reference.py`](egrz/reference.py)):

| Что | Как |
|---|---|
| Даты | три формата (`ISO`, `15.01.2026`, `2026/01/15`) → `YYYY-MM-DD` |
| Стоимость | `"1 234 567,89"`, `"1.234.567,00"`, `"12 345 678 руб."` → `float` |
| Регион | 89 субъектов РФ с псевдонимами (`ХМАО`, `Якутия`, `Кубань`), распознавание по коду и по адресу целиком, привязка к федеральному округу |
| Организация | `ООО "ЭКСПЕРТ"` / `ООО «Эксперт»` / `Общество с ограниченной ответственностью "Эксперт"` → одна строка рейтинга |
| Категория объекта | классификатор по наименованию: жильё, образование, здравоохранение, дороги, инженерные сети, промышленность и ещё 5 категорий |
| Тип, результат, предмет | приводятся к фиксированным значениям для фильтров |
| Стоимостная корзина | 7 диапазонов от «до 10 млн ₽» до «свыше 5 млрд ₽» |

## Ежедневность и инкрементальность

`egrz daily` = `sync` + `export`.

Выгрузка **инкрементальная**: хранилище помнит максимальную дату включения в
реестр и продолжает с неё, отступив назад на `--overlap` дней (по умолчанию 3) —
записи попадают в реестр задним числом, и «хвост» нужно перечитывать.

Изменения отслеживаются по отпечатку содержательных полей: повторный запуск
того же дня даёт `unchanged`, а не ложные обновления. Каждый запуск пишется в
журнал `runs` — вместе со статусом и ошибкой, если выгрузка упала.

```bash
python -m egrz.cli stats     # что сейчас в базе и как прошли последние запуски
```

Расписание — [`.github/workflows/daily.yml`](.github/workflows/daily.yml):
ежедневно в 07:20 МСК, база переносится между запусками через кеш Actions,
витрина публикуется на GitHub Pages и складывается в артефакты.

## Умные фильтры

Дашборд — статические HTML/CSS/JS без зависимостей и сборки.

* **Фасеты с зависимыми счётчиками.** Счётчик в фасете считается так, будто
  выбор *внутри этого же фасета* ещё не сделан. Иначе, выбрав «Москва», вы
  видели бы нули у всех остальных регионов и фильтр становился бы тупиковым.
* **Полнотекстовый поиск** по объекту, адресу, организации, застройщику и
  номерам заключения (строка поиска предвычисляется на загрузке).
* **Период** — пресеты 30/90/365 дней или произвольный диапазон.
* **9 измерений**: федеральный округ, субъект РФ, тип экспертизы, результат,
  категория объекта, назначение, предмет экспертизы, организация, стоимость.
* **Состояние в URL** — ссылкой на конкретный срез можно поделиться.
* Активные условия показаны чипами, снимаются по одному или все сразу.

Данные для дашборда кодируются словарём (повторяющиеся строки заменяются
индексами), поэтому фильтрация идёт по целым числам и десятки тысяч записей
пересчитываются в один кадр.

## Инфографика

Ведущее число, 4 плитки-показателя и 6 графиков — все пересчитываются под
текущий срез:

* динамика включений в реестр по месяцам;
* топ-15 субъектов РФ и категории объектов;
* федеральные округа в разрезе государственной / негосударственной экспертизы;
* распределение по сметной стоимости;
* топ экспертных организаций;
* таблица записей со ссылками на карточки в ЕГРЗ.

У каждого графика есть переключатель **«Таблица»** — та же информация числами,
без опоры на цвет. Палитра проверена на различимость при дальтонизме
(отдельно для светлой и тёмной темы), тема переключается и следует системной.

## Команды

| Команда | Что делает |
|---|---|
| `egrz sync` | выгрузка источника в базу (по умолчанию инкрементально) |
| `egrz export` | сборка витрины: `dataset.json`, `aggregates.json`, `meta.json`, `conclusions.csv` |
| `egrz daily` | `sync` + `export` — то, что запускается по расписанию |
| `egrz discover` | разведка API источника |
| `egrz stats` | состояние базы и журнал запусков |
| `egrz serve` | локальный просмотр дашборда |

Полезные флаги: `--full` (полная выгрузка), `--limit N` (отладка),
`--overlap N` (перекрытие в днях), `--max-rows N` (сколько свежих записей
класть в дашборд; `0` — все, по умолчанию 60 000 — CSV и агрегаты остаются
полными в любом случае).

## Артефакты витрины

| Файл | Содержимое |
|---|---|
| `dataset.json` | записи для дашборда, словарное кодирование |
| `aggregates.json` | готовые срезы (по месяцам, регионам, округам, категориям, организациям, стоимости) для внешних потребителей |
| `meta.json` | время сборки, глубина данных, журнал запусков |
| `conclusions.csv` | полная плоская выгрузка, `;` и UTF-8 BOM — открывается в Excel |

## Тесты

```bash
pip install -e ".[dev]"
python -m pytest -q          # 134 теста
```

Покрыты: разбор дат и стоимости, сведение названий организаций, справочник
регионов и классификатор объектов, пагинация и клиентская фильтрация источника,
инкрементальность и журнал хранилища, кодирование витрины и агрегаты, CLI.

## Оговорки

* `--source demo` создаёт **синтетические** данные — они правдоподобны по форме
  и распределениям, но это не реальный реестр. Витрина, собранная из них,
  годится только для проверки конвейера и внешнего вида.
* Категория объекта и назначение — результат эвристики по наименованию, а не
  официальная классификация; для нестандартных наименований возможна категория
  «Прочее».
* Соблюдайте нагрузку на источник: в конфиге заданы пауза между запросами и
  повторы с экспоненциальным откатом.
