# Фото на память

Приложение-фотобудка для Android и iOS. Планшет ставится на стойку на
мероприятии, гости подходят, фотографируются и сразу забирают напечатанный
снимок.

Печать идёт **напрямую на портативный фотопринтер по IPP** — без системного
диалога печати, из которого гость мог бы уйти в настройки планшета.

Целевой принтер — **Xiaomi Instant / Portable Photo Printer 1S**
(ZPDYJ03HT, в обиходе «S1»): сублимация, 300 dpi, лист 10×15 см,
около 57 секунд на отпечаток.

---

## Главное техническое решение

Для устройства Xiaomi первым делом хочется разбирать проприетарный miIO —
как это делают для пылесосов и лампочек. Здесь это не нужно.

Принтер заявляет поддержку **Mopria, AirPrint и Wi-Fi Direct Print**, а обе
первые технологии — это **IPP** (RFC 8010/8011) поверх HTTP на TCP :631.
Значит, с ним можно говорить документированным стандартным протоколом.

Что это даёт киоску:

- **печать без системного диалога** — обязательное требование для планшета,
  который стоит без присмотра;
- **состояние задания**: видно, когда лист действительно вышел;
- **состояние принтера**: кончилась бумага, открыта крышка, остаток ленты;
- **независимость от модели**: формат документа, размер бумаги и разрешение
  выясняются у принтера в рантайме, поэтому приложение работает и с любым
  другим AirPrint/Mopria-принтером, который окажется на площадке.

Подробности и порядок проверки на живом железе — [`docs/PRINTER.md`](docs/PRINTER.md).

## Запуск

### Проверка логики — работает прямо сейчас

```bash
npm install
npm run verify        # tsc --noEmit + eslint + jest
```

Ни планшета, ни принтера для этого не нужно: весь протокол печати,
геометрия, очередь и сценарий не зависят от React Native и гоняются на Node.

### Сборка приложения

В репозитории лежит код приложения и нативные модули, но не служебные файлы
платформенных проектов (Gradle-скрипты, `MainActivity`, проект Xcode,
`Podfile`). Их генерирует стандартный шаблон React Native:

```bash
# 1. Сгенерировать платформенные проекты во временной папке
npx @react-native-community/cli init PhotoNaPamyat --version 0.76.5 --skip-install

# 2. Скопировать из неё в этот репозиторий:
#    android/  — всё, кроме app/src/main/java/com/photonapamyat/ и AndroidManifest.xml
#    ios/      — проект Xcode и Podfile

# 3. В android/app/build.gradle задать applicationId "com.photonapamyat"
# 4. В MainApplication добавить пакет: new PhotoKioskPackage()
# 5. В Xcode добавить файлы из ios/PhotoNaPamyat/ и подключить Info.plist
# 6. Установить зависимости и запустить
npm install
cd ios && pod install && cd ..
npm run android      # или npm run ios
```

Дальше — [`docs/KIOSK-SETUP.md`](docs/KIOSK-SETUP.md): как превратить планшет
в киоск, из которого нельзя выйти.

## Сценарий гостя

```
Заставка (зеркало) → Выбор формата → Приготовьтесь → 3·2·1 → Снимок
                                                                 ↓
Заставка ← Благодарность ← Печать ← Просмотр («Печатать» / «Переснять»)
```

Из каждого шага есть выход по таймауту: гость может уйти в любой момент, и
будка освободится сама. Из просмотра снимок при бездействии **уходит в печать
сам** — лишний отпечаток дешевле, чем занятая будка и очередь за спиной.

Печать идёт в фоне: экран освобождается сразу после постановки задания, а не
через 57 секунд.

Разбор каждого экрана и обоснование решений —
[`docs/UI-SPEC.md`](docs/UI-SPEC.md).
Кликабельный прототип, который проходит сценарий целиком, —
[`docs/prototype.html`](docs/prototype.html): откройте файл в браузере.

## Форматы отпечатка

| Формат | Кадров | Что получает гость |
|---|---|---|
| Одно фото | 1 | Снимок во весь лист 10×15 |
| **Полоска на двоих** | 3 | Лист печатается двумя одинаковыми половинами с пунктиром: гости разрывают его и забирают по полосе |
| Четыре кадра | 4 | Сетка 2×2 |
| Полароид | 1 | Кадр с широким белым полем под подпись |
| Два кадра | 2 | «До» и «после» |

## Приватность

Камера снимает чужих людей, поэтому планшет не превращается в архив лиц:
исходные кадры удаляются сразу после сборки листа, напечатанный лист — после
печати, всё остальное — автоматически через сутки. В админке есть кнопка
«Стереть все снимки» для конца мероприятия. Сохранение копий выключено по
умолчанию.
