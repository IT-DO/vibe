# Карточка — рабочий SaaS-скелет + курс по вайбкодингу

Это два подарка в одной коробке:

1. **Работающий сервис**, который можно запустить прямо сейчас и начать
   продавать: генератор текстов для карточек товаров на Wildberries и Ozon.
   Регистрация, оплата через ЮKassa, кредиты, списание, ограничения — всё есть.
2. **Методичка** в папке `docs/` — как самому дописывать такой продукт,
   разговаривая с нейросетью, и как за две недели дойти до первых денег.

Если ты не программист — это нормально. Всё, что нужно уметь:
копировать команды в терминал и читать по-русски.

---

## Запуск за 10 минут

Нужен только [Node.js версии 22 или новее](https://nodejs.org). Проверь:

```bash
node -v
```

Если версия меньше 22 — поставь свежий Node с сайта и открой терминал заново.

```bash
# 1. Установить зависимости (один раз, ~1 минута)
npm install

# 2. Создать файл с настройками
cp .env.example .env

# 3. Придумать секрет для сессий и вписать его в .env
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
#    Скопируй результат в строку SESSION_SECRET= в файле .env

# 4. Запустить
npm run dev
```

Открой <http://localhost:3000>. Зарегистрируйся, нажми «Сделать карточку».

Тексты пока выдаёт **заглушка** — так задумано: сервис работает целиком,
без ключей и без денег. Как включить настоящую модель — ниже.

---

## Проверить, что всё цело

```bash
npm run smoke
```

26 проверок: регистрация, вход, генерация, списание кредитов, запрет
работы без кредитов, защита вебхука оплаты от подделки.

**Запускай эту команду после каждого изменения, которое сделала нейросеть.**
Это твоя единственная защита от «работало вчера, сломалось сегодня».
Если внизу написано «Всё хорошо» — можно продолжать. Если нет — покажи
вывод Claude и попроси починить.

## Включить настоящие тексты

В файле `.env` поменяй `LLM_PROVIDER=mock` на один из вариантов:

| Значение | Что это | Что заполнить |
|---|---|---|
| `mock` | Заглушка. Работает без ключей и бесплатно | ничего |
| `anthropic` | Claude — лучшее качество текстов | `ANTHROPIC_API_KEY` |
| `openai-compatible` | Любой сервис с OpenAI-совместимым API, включая российские шлюзы | `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` |

Про доступ к моделям из России — в [docs/03-deploy.md](docs/03-deploy.md).

После смены `.env` перезапусти `npm run dev` — настройки читаются при старте.

## Что где лежит

Тебе почти никогда не придётся открывать эти файлы руками — ты будешь
просить Claude. Но понимать карту полезно: так ты сможешь сказать
«поправь вот тут», а не «где-то что-то не работает».

```
src/
├── app/                    Страницы сайта и API
│   ├── page.tsx            Главная (лендинг) — тут продающий текст
│   ├── pricing/            Тарифы
│   ├── app/                Рабочий кабинет
│   ├── login/ register/    Вход и регистрация
│   ├── legal/              Оферта и политика (ШАБЛОНЫ, заполнить!)
│   └── api/                Всё, что происходит на сервере
│       ├── auth/           Регистрация, вход, выход
│       ├── generate/       Генерация карточки и списание кредита
│       └── billing/        Создание платежа и приём вебхука ЮKassa
│
├── components/             Куски интерфейса
│   └── Generator.tsx       Главный экран продукта
│
└── lib/                    Логика, не привязанная к страницам
    ├── llm.ts              Общение с моделью + ПРОМПТ ПРОДУКТА
    ├── plans.ts            ЦЕНЫ. Менять здесь
    ├── yookassa.ts         Платежи
    ├── credits.ts          Начисление и списание
    ├── db.ts               База данных (один файл в data/)
    ├── auth.ts             Пароли
    └── session.ts          Сессии

docs/                       Методичка — читай по порядку
scripts/smoke.mjs           Тест «всё ли работает»
```

**Три файла, которые ты будешь править чаще всего:**

- `src/lib/llm.ts` — промпт. От него зависит качество продукта.
  Настраивать его через `npm run try-prompt`, а не на глаз.
- `src/lib/plans.ts` — цены.
- `src/app/page.tsx` — текст лендинга. От него зависят продажи.

## Правила безопасности (прочитай один раз, соблюдай всегда)

1. **Файл `.env` никогда не попадает в git.** Там ключи и доступ к деньгам.
   Он уже в `.gitignore` — не убирай его оттуда.
2. **Папка `data/` тоже.** Там пароли пользователей и история платежей.
3. **Никогда не вставляй ключи прямо в код.** Только в `.env`.
   Если Claude предложит вписать ключ в файл с кодом — скажи «нет, через .env».
4. **Делай бэкап базы до каждого обновления.** Для этого есть `./backup.sh`,
   и `./deploy.sh` вызывает его сам. Просто скопировать `data/app.db` —
   недостаточно: база в режиме WAL, и такая копия молча теряет последние
   записи. Подробности — в docs/07-proxmox.md.

## Команды

```bash
npm run dev        # разработка, сайт на localhost:3000
npm run smoke      # проверить, что всё работает
npm run try-prompt # прогнать промпт по 10 товарам и сравнить результат
npm run build      # собрать для сервера
npm start          # запустить собранное
npm run typecheck  # проверить код на ошибки, не запуская
```

На сервере ещё две:

```bash
./install-server.sh --plan   # что установщик собирается сделать
./install-server.sh          # поставить всё на чистую виртуалку
./check-server.sh  # осмотреть сервер: что готово, чего не хватает
./deploy.sh        # обновить сервис (сам делает бэкап перед обновлением)
./backup.sh        # бэкап базы прямо сейчас
```
