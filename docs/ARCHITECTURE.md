# Архитектура

## Главный принцип: логика не знает про React Native

Всё, что можно сломать незаметно — бинарный протокол, геометрия печати,
поведение очереди, сценарий гостя, — вынесено в чистый TypeScript без единого
импорта из `react-native`. Такой код гоняется в юнит-тестах на Node, без
эмулятора, планшета и принтера.

Это не эстетика. Ошибка в кодировщике IPP проявляется как «принтер молчит»,
ошибка в кадрировании — как «у всех обрезаны головы», и обе видны только на
мероприятии, когда исправлять поздно. 337 тестов выполняются за полторы
секунды и ловят это заранее.

```
┌───────────────────────────────────────────────────────────┐
│  ЭКРАНЫ (React Native)                                    │
│  screens/ · components/ · app/                            │
├───────────────────────────────────────────────────────────┤
│  ПЛАТФОРМА (адаптеры к React Native)                      │
│  platform/tcp · mdns · files · kiosk · feedback           │
├───────────────────────────────────────────────────────────┤
│  ЧИСТАЯ ЛОГИКА (проверяется тестами)                      │
│  printing/ipp · printing/pwg · printing/queue             │
│  imaging/geometry · imaging/layouts                       │
│  features/session/machine · utils/                        │
└───────────────────────────────────────────────────────────┘
```

Граница проведена через интерфейсы. Слой печати не создаёт TCP-соединения —
он получает `TcpConnector`; в приложении это `react-native-tcp-socket`, в
тестах — поддельный сокет, который отвечает заранее заготовленными байтами.
Точно так же вынесены наружу часы (`Scheduler`), файлы (`DocumentLoader`),
хранилище очереди и mDNS.

## Слой печати

```
composeSheet()                    собирает лист на Skia -> JPEG
      │
      v
PrintQueue.enqueue()              задание ложится в очередь (файл на диске)
      │
      v
PrintQueue.step()                 фоновый цикл
      │
      ├─> transport.checkStatus() принтер готов? бумага есть?
      ├─> documents.read()        читает файл листа
      ├─> transport.submit()      Print-Job
      └─> transport.trackJob()    опрос до завершения
```

### Транспорты

Очередь работает с интерфейсом `PrinterTransport`, а не с конкретным
принтером. Реализаций три:

| Транспорт | Когда | Диалог печати | Отслеживание |
|---|---|---|---|
| **`IppTransport`** | Основной режим | нет | да |
| `SystemPrintTransport` | Отладка на площадке, крайний случай | **да** | нет |
| `MockTransport` | Разработка, репетиция, демо-стенд | нет | имитирует |

Подмена сделана через прокси в `app/services.ts`: очередь держит одну
ссылку, а транспорт под ней меняется при изменении настроек, не теряя
накопленных заданий.

### Очередь

Причина её существования — 57 секунд на лист. Если бы приложение ждало
завершения печати, гость стоял бы у планшета минуту, а за ним копилась
очередь. Экран освобождается сразу после постановки задания.

Что ещё она берёт на себя:

- **Переживает перезапуск.** Задания лежат в JSON на диске, а не в памяти.
  Задание, застрявшее в состоянии «отправляется» после падения приложения,
  возвращается в очередь: повторная печать лучше, чем гость без фотографии.
- **Повторяет при обрывах.** Экспоненциальная задержка с дрожанием ±20 % —
  чтобы после восстановления Wi-Fi несколько отложенных заданий не ломились
  в принтер одновременно.
- **Различает три вида ошибок.** Временная — повторить; фатальная (принтер
  не понимает формат) — не тратить бумагу и попытки; «нужен человек» (нет
  бумаги, открыта крышка) — встать на паузу, **не потратив попытку**, и
  продолжить самостоятельно, когда оператор всё починил.

## Сценарий гостя

`features/session/machine.ts` — чистая функция
`(состояние, событие, настройки) → (новое состояние, побочные действия)`.

Экраны только рисуют состояние и шлют события. Побочные действия
(`capture`, `enqueuePrint`, `discardShots`, `sound`, `haptic`) выполняет
`app/useKioskSession.ts` — единственное место, где живёт всё, что может
подвиснуть: камера, сборка листа, запись файла.

Почему так: почти все отказы киоска — это залипание в промежуточном
состоянии. Гость ушёл, не нажав «печатать». Ребёнок потыкал в экран. Кто-то
закрыл камеру рукой. Такие сюжеты дёшево проверять тестами и дорого — на
живом мероприятии.

## Сборка отпечатка

`imaging/` разделён на две части:

- **`geometry.ts`** — чистая математика: миллиметры в пиксели, кадрирование
  под ячейку, припуск, сетки. Полностью покрыта тестами.
- **`composer.ts`** — рисование на офскрин-холсте Skia. Здесь тестов нет:
  проверять надо глазами на бумаге.

Раскладка (`layouts.ts`) описывает, сколько кадров снять и как разложить их
по листу. Одна съёмка может попасть в несколько ячеек — так устроена
двойная полоса: лист печатается двумя одинаковыми половинами.

## Зависимости и зачем каждая

| Пакет | Зачем | Можно ли без него |
|---|---|---|
| `react-native-vision-camera` | Камера с контролем качества снимка | Нет |
| `@shopify/react-native-skia` | Сборка листа на офскрин-холсте | Нет: `view-shot` зависит от экрана и не даёт точного размера в пикселях |
| `react-native-tcp-socket` | TCP для IPP | Нет: `fetch` портит бинарное тело |
| `react-native-zeroconf` | mDNS | Да, если всегда вводить адрес вручную |
| `react-native-image-picker` | Печать готового снимка из галереи | Да, если оставить только съёмку |
| `react-native-fs` | Файлы кадров и очереди | Нет |
| `react-native-mmkv` | Настройки | Заменяется на AsyncStorage |
| `zustand` | Состояние настроек | Заменяется на Context |
| `react-native-svg` + `qrcode-generator` | QR цифровой копии | Да, если QR не нужен |

Навигационной библиотеки нет намеренно: сценарий линейный, а `react-
navigation` принесла бы жесты «назад», которые в киоске вредны.

## Что проверяется тестами

| Область | Тестов | Что именно |
|---|---|---|
| Кодек IPP | 19 | Сообщения собраны побайтово по RFC и разобраны обратно, включая коллекции и кириллицу |
| Клиент IPP | 19 | Полный цикл против поддельного принтера: возможности, печать, отслеживание, отказы, таймауты, сборка ответа из TCP-чанков |
| Возможности и HTTP | 39 | Имена носителей PWG, выбор формата, состояние принтера, chunked-кодирование |
| PWG Raster | 29 | Побайтовый round-trip 11 видов изображений, включая полный лист 1200×1800 |
| Очередь | 34 | Порядок, повторы, пауза при «нет бумаги», восстановление после перезапуска, отмена |
| Поиск принтера | 20 | mDNS, шлюз, приоритет фотопринтера, сеть без multicast |
| Геометрия и раскладки | 74 | Кадрирование, припуск, границы ячеек, двойная полоса |
| Сценарий сессии | 36 | Все переходы, таймауты, отмена, полный путь гостя |
| Транспорты и ошибки | 23 | Согласование формата и носителя, классификация сбоев, задержки повторов |
| Байты и base64 | 44 | UTF-8, big-endian, векторы RFC 4648 |
