# Контекст проекта

Сервис генерации текстов для карточек товаров на Wildberries и Ozon.
Аудитория — продавцы маркетплейсов в России. Владелец проекта не программист:
он ставит задачи словами и проверяет результат по поведению, а не по коду.

Стек: Next.js (App Router) + TypeScript, SQLite через better-sqlite3,
оплата через ЮKassa, языковая модель за абстракцией в `src/lib/llm.ts`.

# Как со мной работать

- Объясняй решения простыми словами. Я не программист — «мы вынесли
  это в отдельный модуль» мне ничего не говорит, а «теперь цены лежат
  в одном месте, и их можно менять, не боясь сломать оплату» говорит.
- Для всего, что касается денег, паролей, доступов и базы: сначала план
  и моё «ок», потом код.
- После изменений перечисляй, что тронул, и запускай `npm run smoke`.
- Не добавляй новые библиотеки без объяснения, зачем именно эта.
- Если чиним одно и то же третий раз — останавливайся и предлагай
  другой подход, а не четвёртую попытку.

# Правила проекта

- Все тексты интерфейса — на русском, обращение к пользователю на «ты».
- Цены только в `src/lib/plans.ts`. Больше нигде числами не писать.
- Промпт продукта — константа `SYSTEM_PROMPT` в `src/lib/llm.ts`.
- Секреты только через `.env`. Никогда не вписывать ключи в код.
- Каждая новая функция получает проверку в `scripts/smoke.mjs`.
- Списание кредитов и запись результата — всегда в одной транзакции.
- Вебхук оплаты обязан оставаться идемпотентным: повторная доставка
  одного платежа не должна начислять кредиты дважды.

# Команды

```bash
npm run dev        # разработка
npm run smoke      # 26 проверок сквозного сценария
npm run typecheck  # проверка типов
npm run build      # сборка
```

# Чего не делать

- Не менять схему базы без миграции существующих данных.
- Не убирать проверку IP и перезапрос платежа в вебхуке ЮKassa.
- Не хранить пароли иначе как хэшем.
- Не логировать содержимое `.env`, ключи и пароли.
