# Выложить в интернет

Цель: адрес вида `https://твой-домен.ру`, который можно скинуть в чат.

---

## Где размещать

**Бери российский хостинг.** Не из патриотизма, а по двум причинам:

1. **152-ФЗ.** Персональные данные россиян (а почта пользователя — это
   персональные данные) должны храниться в базе на территории России.
   Твоя база — файл `data/app.db` на сервере. Значит, сервер должен быть в РФ.
2. **Оплата.** Российской картой хостинг за рубежом ты сейчас не оплатишь.

Подойдёт любой VPS от 200–500 ₽ в месяц: Timeweb Cloud, Selectel, Beget,
REG.RU, Cloud.ru. Бери самый дешёвый тариф с **2 ГБ памяти** и Ubuntu 24.04 —
этого хватит на первые сотни пользователей с запасом.

---

## Про доступ к модели из России

Anthropic официально Россию не обслуживает — проверь актуальный список
стран на их сайте перед тем, как рассчитывать на прямой доступ.
Поэтому в проекте предусмотрены два пути, и переключение между ними —
одна строка в `.env`, без правки кода.

| Путь | Как включить | Когда подходит |
|---|---|---|
| Claude напрямую | `LLM_PROVIDER=anthropic` + `ANTHROPIC_API_KEY` | Если у тебя есть легальный доступ (например, юрлицо в другой стране) |
| Любой сервис с OpenAI-совместимым API | `LLM_PROVIDER=openai-compatible` + `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | Российские провайдеры моделей и шлюзы. Большинство из них даёт совместимый эндпоинт |

Что делать практически: выбери провайдера, доступного тебе легально,
открой его документацию и найди раздел про OpenAI-совместимость. Оттуда
нужны три вещи — адрес API, ключ и название модели. Впиши их в `.env`.

Проверить, что связка работает:

```bash
npm run dev
# зарегистрируйся, сделай генерацию
# если в описании нет надписи [ЗАГЛУШКА] — модель подключилась
```

**Считай себестоимость.** Раздели цену тысячи токенов на своего провайдера
на количество карточек. Одна карточка — примерно 1500–2500 токенов ответа.
Если себестоимость получается выше трети от цены продажи — поднимай цены
в `src/lib/plans.ts` или бери модель попроще. Это надо посчитать **до**
запуска, а не после первой сотни продаж.

## Установка на сервер

Дальше — команды. Выполняй по порядку, каждую отдельно. Если что-то
пошло не так, скопируй ошибку целиком и покажи Claude.

### 1. Зайти на сервер

Хостер пришлёт адрес, логин `root` и пароль.

```bash
ssh root@АДРЕС_СЕРВЕРА
```

### 2. Поставить Docker

```bash
curl -fsSL https://get.docker.com | sh
```

Docker — это способ запустить приложение вместе со всем, что ему нужно,
одной командой. Без него пришлось бы вручную ставить Node нужной версии,
настраивать автозапуск и разбираться, почему на сервере работает не так,
как на ноутбуке.

### 3. Забрать код

```bash
apt update && apt install -y git
git clone АДРЕС_ТВОЕГО_РЕПОЗИТОРИЯ /opt/app
cd /opt/app
```

### 4. Настройки

```bash
cp .env.example .env
nano .env
```

Заполни:

- `APP_URL=https://твой-домен.ру` — обязательно с https;
- `SESSION_SECRET` — новый, **не тот же, что на ноутбуке**;
- настройки модели;
- `YOOKASSA_*` — когда дойдёшь до [подключения оплаты](04-yookassa.md);
- `DATABASE_PATH=/data/app.db` — так уже прописано в Dockerfile, не меняй.

Сохранить в nano: `Ctrl+O`, `Enter`, `Ctrl+X`.

Сгенерировать секрет прямо на сервере:

```bash
openssl rand -hex 32
```

### 5. Запустить

```bash
docker compose up -d --build
```

Первая сборка — несколько минут. Проверь:

```bash
curl -I http://127.0.0.1:3000
```

Должно ответить `HTTP/1.1 200 OK`.

### 6. Домен и HTTPS

Купи домен (REG.RU, Timeweb, nic.ru — от 200 ₽/год в зоне .ru).
В панели управления доменом создай **A-запись**, указывающую на IP сервера.
Изменения расходятся от нескольких минут до пары часов.

HTTPS обязателен: без него браузер покажет «Не защищено», а ЮKassa
не примет вебхуки. Самый простой способ — Caddy, он получает сертификат сам:

```bash
apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy
```

Настрой:

```bash
nano /etc/caddy/Caddyfile
```

Всё содержимое файла — три строки (подставь свой домен):

```
твой-домен.ру {
    reverse_proxy 127.0.0.1:3000
}
```

```bash
systemctl reload caddy
```

Открой `https://твой-домен.ру`. Замок в адресной строке — значит, готово.

## Обновление после изменений

Ты правишь код на ноутбуке, проверяешь, отправляешь в репозиторий:

```bash
npm run smoke                     # СНАЧАЛА проверить
git add -A && git commit -m "что сделал"
git push
```

На сервере:

```bash
cd /opt/app
./deploy.sh
```

Скрипт `deploy.sh` лежит в проекте: он делает бэкап базы, забирает
изменения и пересобирает контейнер.

## Бэкапы

База — это один файл. Потерять его — значит потерять всех пользователей
и историю платежей.

Разовый бэкап:

```bash
cp /opt/app/data/app.db ~/backup-$(date +%F).db
```

Автоматический, каждую ночь в 4:00:

```bash
crontab -e
```

Добавь строку:

```
0 4 * * * cp /opt/app/data/app.db /root/backup-$(date +\%F).db && find /root -name 'backup-*.db' -mtime +14 -delete
```

Хранит две недели, старое удаляет.

**Раз в неделю скачивай бэкап себе на ноутбук.** Бэкап на том же сервере
не спасёт, если сервер пропадёт целиком:

```bash
scp root@АДРЕС:/root/backup-*.db ~/Downloads/
```

## Если что-то сломалось

```bash
docker compose logs --tail 100    # последние 100 строк логов
docker compose ps                 # запущено ли вообще
docker compose restart            # перезапустить
docker compose up -d --build      # пересобрать с нуля
```

Логи — это то, что нужно копировать и показывать Claude целиком.
Не пересказывай своими словами: в ошибке важна каждая строка.
