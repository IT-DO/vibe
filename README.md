# Фото на память

Приложение-фотобудка для Android. Планшет ставится на стойку на
мероприятии, гости подходят, фотографируются и сразу забирают напечатанный
снимок.

Печать идёт **напрямую на принтер** — без системного диалога печати, из
которого гость мог бы уйти в настройки планшета, и без приложения Xiaomi
Home.

Целевой принтер — **Xiaomi Portable Photo Printer 1S**, модель
**BHR9974GL**: технология ZINK (краситель запечён в бумагу, чернил нет),
карманная бумага 2 × 3″ (50 × 76 мм), около 45 секунд на отпечаток, связь
только по Bluetooth.

---

## Главное техническое решение

У принтера **нет Wi-Fi**. Значит нет ни AirPrint, ни Mopria, ни IPP — всей
той стандартной сетевой печати, на которую обычно рассчитывают. Штатно он
печатает единственным способом: из приложения Xiaomi Home по закрытому
протоколу поверх Bluetooth.

Протокол разобран по журналу Bluetooth с настоящей печати и реализован
целиком — см. [`docs/BLUETOOTH-PROTOCOL.md`](docs/BLUETOOTH-PROTOCOL.md).
Коротко:

- это **классический Bluetooth** (профиль последовательного порта), а не
  Bluetooth Low Energy — в журнале нет ни одного пакета ATT;
- кадры с собственным заголовком, тело зашифровано **AES-128-ECB**;
- ключ вырабатывается заново при каждом подключении по Диффи — Хеллману,
  поэтому **ни учётной записи Xiaomi, ни miio-токена не нужно**;
- принтер принимает **baseline JPEG ровно 1040 × 1560** — картинку больше
  он не уменьшает, а обрезает по центру.

Записанный сеанс удалось расшифровать целиком: модуль Диффи — Хеллмана,
который выдаёт прошивка, оказался составным и гладким, так что секрет
восстанавливается решением дискретного логарифма. Благодаря этому тесты
сверяются не сами с собой, а с байтами, которые реально ушли в принтер:
собранные кадры совпадают с перехваченными побайтово, а рукопожатие
воспроизводит записанный сеанс вместе с ключом.

Что это даёт киоску:

- **печать без системного диалога** — обязательное требование для планшета,
  который стоит без присмотра;
- **состояние задания**: видно, когда лист действительно вышел;
- **состояние принтера**: заряд, остаток до чистки, замятая бумага,
  открытая крышка;
- **очередь**, которая переживает перезапуск приложения и встаёт на паузу,
  когда принтеру нужен человек.

Слой IPP тоже оставлен — он работает с сетевыми принтерами, если такой
окажется на площадке. Канал печати выбирается в админке.

Подробности и порядок настройки на площадке — [`docs/PRINTER.md`](docs/PRINTER.md).

замятии — проверяется только на железе. Порядок проверки расписан в
[`docs/PRINTER.md`](docs/PRINTER.md).

## Запуск

### Проверка логики — работает прямо сейчас

```bash
npm install
npm run verify        # tsc --noEmit + eslint + jest
```

Ни планшета, ни принтера для этого не нужно: весь протокол печати,
геометрия, очередь и сценарий не зависят от React Native и гоняются на Node.

### Сборка приложения

Платформенные проекты лежат в репозитории и настроены: нативные модули
подключены к целям сборки, разрешения прописаны. Генерировать шаблон не нужно.

**APK без установки инструментов** — раздел **Releases**, релиз
`android-latest`. Прямая ссылка на `.apk`, обновляется каждой успешной
сборкой; открывается прямо в браузере телефона.

**APK на своей машине** (нужны JDK 17, Android SDK 35, NDK 26.1.10909125):

```bash
npm install
cd android && ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
# android/app/build/outputs/apk/release/app-release.apk
```

**iOS заморожен.** Проект под iPad настроен и проверенно компилируется, но
развитие сосредоточено на Android: там нет ежегодной платы, сертификатов и
ограничений на установку, а киоск-режим работает по-настоящему. Файлы
оставлены в репозитории — ветку можно разморозить, ничего не восстанавливая.
Сборка под iOS убрана из автоматических прогонов и запускается вручную:
Actions → «Сборка» → Run workflow → галка «Собрать также под iOS».

Подробно — включая подпись релиза и разбор ошибок сборки —
в [`docs/BUILD.md`](docs/BUILD.md).

Дальше — [`docs/KIOSK-SETUP.md`](docs/KIOSK-SETUP.md): как превратить планшет
в киоск, из которого нельзя выйти.

## Сценарий гостя

```
Заставка (зеркало) → Выбор формата → Приготовьтесь → 3·2·1 → Снимок
                                                                 ↓
Заставка ← Благодарность ← Печать ← Просмотр («Печатать» / «Переснять»)
```

Есть и второй путь: кнопка **«Выбрать готовое фото»** на заставке открывает
галерею и печатает уже имеющийся снимок, минуя съёмку.

Из каждого шага есть выход по таймауту: гость может уйти в любой момент, и
будка освободится сама. Из просмотра снимок при бездействии **уходит в печать
сам** — лишний отпечаток дешевле, чем занятая будка и очередь за спиной.

Печать идёт в фоне: экран освобождается сразу после постановки задания, а не
через 57 секунд.

Разбор каждого экрана и обоснование решений —
[`docs/UI-SPEC.md`](docs/UI-SPEC.md).
Кликабельный прототип, который проходит сценарий целиком, —
[`docs/prototype.html`](docs/prototype.html): откройте файл в браузере.

## Форматы отпечатка

| Формат | Кадров | Что получает гость |
|---|---|---|
| Одно фото | 1 | Снимок во весь лист 10×15 |
| **Полоска на двоих** | 3 | Лист печатается двумя одинаковыми половинами с пунктиром: гости разрывают его и забирают по полосе |
| Четыре кадра | 4 | Сетка 2×2 |
| Полароид | 1 | Кадр с широким белым полем под подпись |
| Два кадра | 2 | «До» и «после» |

## Приватность

Камера снимает чужих людей, поэтому планшет не превращается в архив лиц:
исходные кадры удаляются сразу после сборки листа, напечатанный лист — после
печати, всё остальное — автоматически через сутки. В админке есть кнопка
«Стереть все снимки» для конца мероприятия. Сохранение копий выключено по
умолчанию.
