# Подключить ЮKassa

Здесь появляются настоящие деньги, поэтому читай внимательнее обычного.
Порядок такой: сначала оформить статус, потом магазин, потом настройки,
потом обязательно тестовый платёж на живые рубли.

---

## Что нужно до начала

**Статус самозанятого или ИП.** Без него принимать платежи нельзя.
Самозанятость оформляется за вечер через приложение «Мой налог», налог 6 %
с поступлений от юрлиц и 4 % от физлиц. Подробнее — в
[docs/06-legal.md](06-legal.md).

**Заполненная оферта.** Файл `src/app/legal/offer/page.tsx` — это шаблон
с полями в квадратных скобках. Заполни свои данные и выложи на сайт
до подключения. ЮKassa при проверке магазина смотрит на неё.

**Работающий сайт по HTTPS.** Вебхуки приходят только на https-адрес.
Если сайта ещё нет — сначала [деплой](03-deploy.md).

---

## Шаг 1. Магазин

1. Зарегистрируйся на <https://yookassa.ru>.
2. Создай магазин, укажи адрес сайта.
3. Заполни анкету: вид деятельности, реквизиты, ссылка на оферту.
4. Дождись проверки — обычно от нескольких часов до пары дней.

Пока идёт проверка, можно работать в тестовом режиме — ЮKassa выдаёт
отдельные тестовые `shopId` и ключ. На них проходят платежи с тестовых
карт из документации ЮKassa, деньги не двигаются.

---

## Шаг 2. Ключи в `.env`

В личном кабинете ЮKassa: **Интеграция → Ключи API**.

Нужны два значения:

- **shopId** — номер магазина, его можно показывать;
- **Секретный ключ** — как пароль от кошелька.

```bash
YOOKASSA_SHOP_ID=123456
YOOKASSA_SECRET_KEY=live_ВАШ_КЛЮЧ
```

> Секретный ключ никогда не попадает в git, в переписку и в код.
> Только в `.env` на сервере. Если он куда-то утёк — немедленно
> перевыпусти его в кабинете, старый перестанет работать.

Перезапусти сервис. На странице «Тарифы» жёлтая плашка «оплата
подключается» исчезнет, кнопки станут рабочими.

---

## Шаг 3. Вебхук

Вебхук — это то, как ЮKassa сообщает твоему сайту «платёж прошёл,
начисляй». Без него человек заплатит, а кредиты не появятся.

В кабинете: **Интеграция → HTTP-уведомления**.

- Адрес: `https://твой-домен.ру/api/billing/yookassa/webhook`
- События: **payment.succeeded** и **payment.canceled**

Проверить, что адрес виден снаружи:

```bash
curl -X POST https://твой-домен.ру/api/billing/yookassa/webhook \
  -H "content-type: application/json" -d '{}'
```

Ответ `forbidden` — **это правильно**. Значит, обработчик жив и отшил
чужой запрос: ты не с адресов ЮKassa. Если пришло `404` — проверь адрес.
Если ничего — проверь, что HTTPS работает.

---

## Шаг 4. Чеки по 54-ФЗ

Если у тебя подключена онлайн-касса, каждый платёж должен сопровождаться
чеком. В проекте это уже есть — включается одной строкой:

```bash
YOOKASSA_SEND_RECEIPT=true
```

**Если кассы нет — оставь `false`**, иначе ЮKassa будет отклонять платежи
с ошибкой про чек.

Ставку НДС проверь у бухгалтера: в `src/lib/yookassa.ts` стоит `vat_code: 1`
(без НДС) — для самозанятого и ИП на УСН это обычно верно, но твой случай
может отличаться.

---

## Шаг 5. Тестовый платёж на настоящие деньги

**Не пропускай этот шаг.** Тестовый магазин проверяет не всё: боевые
ключи, боевые вебхуки и боевой домен ведут себя иначе.

1. Временно добавь в `src/lib/plans.ts` тариф на 10 ₽ за 1 генерацию.
2. Задеплой.
3. Купи его со своей карты, как обычный покупатель.
4. Проверь по порядку:
   - тебя вернуло на `/app` с зелёной плашкой «Оплата принята»;
   - счётчик генераций вырос;
   - в кабинете ЮKassa платёж со статусом «Успешный»;
   - в логах есть строка про начисление:
     ```bash
     docker compose logs | grep webhook
     ```
5. Удали тестовый тариф из `plans.ts` и задеплой снова.

Если кредиты не начислились — смотри раздел «Если что-то не работает».

## Как это устроено внутри

Пригодится, когда будешь что-то менять. Пять шагов:

1. Человек жмёт «Оплатить» → `src/components/BuyButton.tsx`
2. Сервер создаёт платёж в ЮKassa и записывает его в свою базу
   со статусом `pending` → `src/app/api/billing/checkout/route.ts`
3. Человека уводит на страницу оплаты ЮKassa
4. После оплаты ЮKassa стучится в наш вебхук →
   `src/app/api/billing/yookassa/webhook/route.ts`
5. Вебхук перепроверяет платёж и начисляет кредиты

**Три защиты, которые уже стоят.** Если будешь править биллинг — не снеси
их случайно:

- **Проверка отправителя.** Запрос принимается только с IP-адресов ЮKassa.
  Иначе кто угодно послал бы «оплачено» и получил кредиты бесплатно.
- **Перезапрос платежа.** Телу вебхука мы не верим — сами спрашиваем
  у ЮKassa статус по номеру платежа. Подделать это нельзя.
- **Защита от повторов.** ЮKassa шлёт уведомление снова, пока не получит
  ответ `200`. Один платёж придёт несколько раз, а начислить нужно один раз.
  За это отвечает поле `credits_issued` в таблице платежей.

## Если что-то не работает

**Кнопка «Оплатить» пишет «Не удалось создать платёж»**

```bash
docker compose logs --tail 50 | grep checkout
```

Обычно: неверные ключи, магазин не прошёл проверку, или включён
`YOOKASSA_SEND_RECEIPT=true` без подключённой кассы.

**Платёж прошёл, кредиты не начислились**

Смотри в кабинете ЮKassa раздел HTTP-уведомлений — там видно, какой
ответ вернул твой сервер.

- `403` → сработала проверка IP. Скорее всего, обратный прокси не передаёт
  настоящий адрес клиента. Каждая строка в логе `webhook: отклонён запрос
  с постороннего адреса` покажет, какой адрес пришёл.
- `500` → не удалось перезапросить платёж. Проверь `YOOKASSA_SECRET_KEY`.
- `200`, но кредитов нет → платежа нет в базе. Проверь, что человек
  начинал оплату с твоего сайта, а не по прямой ссылке.

**Отладка на ноутбуке.** Вебхуки не приходят на `localhost` — нужен
туннель наружу (например, `cloudflared tunnel`). На время отладки
поставь `YOOKASSA_VERIFY_IP=false`: проверка по IP отключится, но
перезапрос платежа в API останется — подделать всё равно не выйдет.
**На сервере верни `true`.**

---

## Возвраты

Первое время делай их руками через кабинет ЮKassa — кнопка «Вернуть»
на странице платежа. Кредиты списывай тоже руками, попроси у Claude команду.

Автоматические возвраты добавляй, когда их станет больше пяти в неделю.
Раньше — не стоит: код без нагрузки протухает, а руками ты заодно
поговоришь с недовольным клиентом и узнаешь, что не так с продуктом.
